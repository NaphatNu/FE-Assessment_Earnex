**Depends on: phase 01 (Trader fields exist). Blocks: phase 04, phase 05.**

**Cannot be delegated to OpenRouter/`ccr code`.** This phase needs live Figma MCP
tool access (Figwright), which only this Claude Code session has. Run it directly.

## Why this phase exists

`docs/03-ui-and-figma.md` describes the design in prose, written before this session
had a working connection to the real Figma file. Phases 04 and 05 were scoped from
that prose. Prose is not measurements — spacing, colors, exact type scale, corner
radii, and the real chip/sheet layer names were guessed, not read. This phase reads
them for real so 04/05 can match Figma instead of approximating it.

## Tasks

1. `get_design_context` on all three node IDs. Do not eyeball a screenshot for any
   measurement — screenshots are for visual verification only, `get_design_context`
   is the source of truth for numbers.
2. `get_styles` + `get_variable_defs` — pull the real color tokens, type styles,
   spacing/radius tokens used by the card, chips, and sheet.
3. `component_map` + `token_map` + `icon_map` — check whether local code (from
   phase 01/02, if already merged) has anything reusable; note matches.
4. `get_reactions` on the UI screen node — read the actual prototype transition
   into the filter sheet (modal vs push, height, animation) instead of assuming
   `showModalBottomSheet` defaults.
5. `save_screenshots` of the component and UI node, saved under `.ai/figma/` (local,
   gitignored) — for visual QA in 04/05, not for measuring.
6. Reconcile against the three deviations `docs/03-ui-and-figma.md` already claims
   (Sharpe Ratio replacing Days Leading Trading; sheet has more groups than the
   task requires; a tag exists in data with no chip). Confirm each still holds
   against the live file, or note if the design has since changed.
7. Write `docs/05-figma-extraction.md` — the grounded spec phase 04/05 must follow:
   - exact spacing/padding/margin values (px) for `TraderCard` and the filter sheet
   - exact type styles (family, size, weight, line-height) per text role
   - exact colors (hex or variable name) per element, including selected vs
     unselected `TagChip`
   - corner radii, elevation/shadow values
   - exact layer/component names from Figma next to the widget each maps to
   - exact copy/labels (button text, section headers) verbatim from the file
   - the real sheet-open transition from step 4
