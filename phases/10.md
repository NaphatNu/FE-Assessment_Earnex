## Why this phase exists

`docs/05-figma-extraction.md` closes with the instruction that every hex and spacing value is
to be mapped to a named token, "not raw literals". The Figma-alignment work did exactly that
for the card, the header, the tabs and the sheet — but never touched the four loading/error/
empty widgets, which were written in an earlier phase. Fourteen raw literals are left, and
they are the reason `grep "0xFF"` does not yet come back empty. Same colours, same pixels —
only the spelling changes.

## Task 1 — add the one missing token

`#CCCCCC` is the sheet grabber pill, read from Figma (`Frame 22`, 36x5, `radius:100`). It has
no token yet. Add to `AppColors`, next to the other semantic entries:

```dart
  /// The drag-handle pill at the top of a bottom sheet — Figma `Frame 22`.
  static const sheetGrabber = Color(0xFFCCCCCC);
```

## Task 2 — substitute, one for one

| literal | replace with | where |
|---|---|---|
| `Color(0xFFCCCCCC)` | `AppColors.sheetGrabber` | `filter_bottom_sheet.dart` (grabber) |
| `Color(0xFF707A8A)` on an `Icon` | `AppColors.iconSecondary` | `empty_filtered_state`, `empty_no_data_state` |
| `Color(0xFF707A8A)` on a `TextStyle` | `AppColors.textSecondary` | `error_state` (the detail line) |

| `Color(0xFFF0B90B)` | `AppColors.bgBrand` | `empty_filtered_state`, `error_state` (button fill) |
| `Color(0xFFF6465D)` | `AppColors.textError` | `error_state` (the error icon) |
| `Color(0xFFEAECEF)` | `AppColors.borderDefault` | `skeleton_card` (card border and the bars) |

`Colors.transparent` in `main.dart` and `filter_icon_with_badge.dart` stays as it is — it is
absence of colour, not a design value.

## Task 3 — the same for type and geometry, only where a token matches exactly

| literal | replace with |
|---|---|
| `TextStyle(fontSize: 16, fontWeight: FontWeight.w600)` | `AppText.semiBold16` (16/22 — the same face, now with the design line-height) |
| `TextStyle(fontSize: 12)` on the error detail | `AppText.regular12` |
| `TextStyle(fontWeight: FontWeight.w600)` on a button label | `AppText.semiBold14` |
| `SizedBox(height: 4 / 8 / 12 / 16 / 32)` | `AppSpacing.x4 / x8 / x12 / x16 / x32` |
| `BorderRadius.circular(8)` | `BorderRadius.circular(AppRadius.md)` |
| `EdgeInsets.symmetric(horizontal: 32)` | `AppSpacing.x32` |

Leave alone anything with no exact token: the `size: 48` icons, the skeleton bar dimensions
(`120`, `70`, `140`, `100`, `28`, `44`), `padding: EdgeInsets.fromLTRB(15, 17.5, 15, 16)`.
Do **not** invent tokens for them — a token that exists in code but not in Figma is worse than
a literal.

Adding the design line-heights (`16/22` instead of the font default) shifts these blocks by a
pixel or two. That is the intended correction, not a regression; the state widget tests assert
text and buttons, not offsets, so they must keep passing untouched.
