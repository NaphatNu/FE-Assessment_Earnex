# Phase 07 — Restructure `lib/src/` to feature-first

**Phase 7 of 12. Depends on: the Figma-alignment UI branch merged into `main`. Blocks: phases 08–12.**

**Execution: delegate via the `openrouter-agent` skill (coding tier).** Purely mechanical —
file moves plus import rewrites. **No behaviour change. No logic edits. No reformatting of
file bodies.** The diff is a rename per file, which is easy to verify without re-reading the
logic, so this is exactly the shape of task the skill is for.

## Why this phase exists

`lib/src/` is a *package* convention — it hides implementation from external importers,
and an app has none. The house convention is feature-first: `lib/data/`, `lib/theme/`,
`lib/features/<feature>/{domain,presentation}/`. This was never decided in `docs/`;
the `lib/src/...` paths were written into phases 01–06 by mistake and every phase
inherited them. This phase corrects the tree once, before anything else is built on it.

## Preconditions — check first, stop if unmet

1. `lib/src/ui/theme/tokens.dart` and `lib/src/ui/sparkline.dart` exist (proof the UI
   branch is merged). If they do not, **stop** — running this against the pre-UI tree
   produces rename-vs-modify conflicts on every UI file.
2. Baseline, recorded before any move: `flutter test` → **35 passing**, `flutter analyze` → 0.

## Task 2 — rewrite imports

Every import in this project is package-absolute (`package:fe_assessment_earnex/src/...`).
Keep them package-absolute; only the path segment changes. Mechanical rule:

```
package:fe_assessment_earnex/src/data/traders_repository.dart
  -> package:fe_assessment_earnex/data/traders_repository.dart
package:fe_assessment_earnex/src/domain/<f>.dart
  -> package:fe_assessment_earnex/features/portfolio/domain/<f>.dart
package:fe_assessment_earnex/src/providers.dart
  -> package:fe_assessment_earnex/features/portfolio/presentation/portfolio_providers.dart
package:fe_assessment_earnex/src/ui/theme/tokens.dart
  -> package:fe_assessment_earnex/theme/tokens.dart
package:fe_assessment_earnex/src/ui/<rest>
  -> per the table above
```

Import blocks stay sorted the way `dart format` leaves them; do not reorder by hand.

## Rules

- `git mv` only — the diff for each file must be a rename, and the only changed lines
  inside a file are `import` lines.
- **Do not** rename any class, provider, method, or test.
- **Do not** edit `phases/01.md`–`phases/06.md`. They are the historical record of what was
  ordered at the time; the old→new path map is recorded in phase 11 instead.
- **Do not** edit `README.md` or `docs/` in this phase (phase 11 owns those).
- **Do not** add barrel files (`portfolio.dart`, `widgets.dart`, …).
