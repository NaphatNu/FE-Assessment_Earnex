## Task 1 — `PortfolioListPage` is not a consumer

It is declared `ConsumerWidget` and takes a `WidgetRef ref`, but its `build` is a single
`const Scaffold(...)` that never reads `ref`. Make it a `StatelessWidget`
(`Widget build(BuildContext context)`) and drop the now-unused
`package:flutter_riverpod/flutter_riverpod.dart` import. Nothing inside the tree changes — the
page's children (`TraderList`, `FilterIconWithBadge`) are the consumers, which is the point of
the design: the page itself has nothing to watch.

`test/app_smoke_test.dart` pumps it inside a `ProviderScope` and must stay green untouched.

## Task 2 — `FilterState._setsEqual` is not per-instance

```dart
  // Helper method to compare sets for equality
  bool _setsEqual(Set<String> a, Set<String> b) {
```

It reads no instance state, so make it `static bool _setsEqual(...)`, and replace the comment —
a comment that restates the signature earns nothing. If a comment stays, it should say *why*:
`Set` has no value equality in Dart, and `==`/`hashCode` here must agree with the `hashCode`
above, which sorts the tags. Do not change the comparison logic or `hashCode`.

## Task 3 — dissolve `filter_gap_test.dart`

The name says nothing, and its seven tests duplicate the subjects of files that already exist.
Move each test **verbatim** — same name, same body — into the file that owns its subject, then
delete `filter_gap_test.dart`:

| test | goes to |
|---|---|
| `filteredTradersProvider shows AsyncLoading initially` | `filtered_traders_provider_test.dart` |
| `filteredTradersProvider shows AsyncData after loading completes` | `filtered_traders_provider_test.dart` |
| `filteredCountProvider is null while loading` | `filtered_traders_provider_test.dart` (the `filteredCountProvider` group) |
| `filtered providers update when filter is applied` | `filtered_traders_provider_test.dart` |
| `Draft/applied separation test` | `draft_filter_provider_test.dart` |
| `Draft seeding test` | `draft_filter_provider_test.dart` |
| `autoDispose discard-on-relisten test` | `draft_filter_provider_test.dart` |

Put each test inside the destination file's existing `group`, keep its name character-for-character
so the move is verifiable in the run output, and merge imports without duplicating them.

## Out of scope — deliberately not done

- **Renaming `MyApp` / extracting `lib/app.dart`.** Conventional, but it touches `main.dart`,
  the smoke test and every screenshot-worthy entry point for zero behavioural gain.

  API changes in 3.x; the migration would touch every provider and the whole of
  `docs/01-provider-design.md`. Phase 11 corrects the one sentence that implied we were already
  on 3.x. Revisit after the assessment is submitted, as its own phase, or not at all.
