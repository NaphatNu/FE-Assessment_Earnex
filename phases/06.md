## Goal
Loading / error / empty states per `docs/04-data-and-ui-states.md`, plus the project README.

## 1. UI states in `TraderList`
`switch` on the `AsyncValue` from `filteredTradersProvider`:
- **loading** → skeleton list (3–5 shimmer-less grey placeholder cards), not a bare spinner
- **error** → message + **Retry** button calling `ref.invalidate(tradersProvider)`
- **data, empty because no traders at all** → "No traders available"
- **data, empty because the filter excluded everything** → distinct state: "No traders match your filter" + **Clear filter** button calling `appliedFilterProvider.notifier.clear()`

The two empty states must be **separate widgets with different copy** — distinguish by `ref.watch(appliedFilterProvider).isEmpty`. Put them in `lib/src/ui/states/`.

Note: with OR semantics the filtered-empty state is unreachable from the mock data (docs/04). Still implement it, and cover it with a widget test that overrides `tradersRepositoryProvider` with a fake returning traders whose tags do not intersect the applied filter.
